立体化关系证据网与诊断证据包

第一版先构建以冒溢节点为锚点的最小关系证据网，把降雨背景、地表积水响应、节点冒溢证据和上下游管段流态组织为可追溯的诊断输入。

node-centered evidence package
Layer 1 对象层

地表 cell、检查井 node、管段 link，以及后续可扩展的泵站、排口、排水分区和降雨事件。

Layer 2 关系层

node_near_cell、cell_adjacent_to_cell、node_connected_to_link、link_upstream/downstream_of_link。

Layer 3 证据层

积水深度、积水时长、节点溢流量、冒溢时长、管段充满度、流向变化和降雨强度等级。

证据包字段说明

证据包不是最终结论，而是把一个冒溢节点周边的对象、关系和证据重组为局部诊断场景。

anchor冒溢节点 ID、触发原因、节点证据 ID。
rainfall_context累计雨量、历时、峰值强度、峰值时刻、强度等级。
node_evidence总溢流量、最大溢流流量、冒溢持续时间、反复冒溢次数。
surface_context附近积水 cell、距离、最大水深、积水时长、邻域淹没 cluster。
network_context相连管段、上下游追溯、充满度、流量、流向变化。
relation_pathsnode-cell-link 的对象链、关系链和 evidence_id，用于核查。
diagnosis_ready_signals将关键条件整理成布尔信号，供 DiagnosisAgent 稳定读取。

筛查机制与诊断证据链的融合

环节 做什么 输出 边界
异常筛查 从海量模拟结果中筛出异常对象。 高积水 cell、冒溢 node、高负荷 link。 只回答哪里异常。
关系建网 建立 node-cell-link 的空间邻近和拓扑关系。 evidence_relation_table.csv 只描述对象如何相连。
证据打包 围绕冒溢节点重组降雨、地表、节点和管段证据。 overflow_node_evidence_packages.json 提供诊断输入，不提前给最终成因。
Agent 诊断 沿关系路径判断地表响应、上游来水、下游受限和雨情语境。 关系型 diagnosis claims。 结论必须指向 evidence_id 和 relation_path。
筛查发现异常点 建网解释异常点 证据包降低 token 消耗 核查机制约束无依据结论

汇报表达

关系证据网的第一版以冒溢节点为诊断锚点，不让大模型直接面对全量模拟结果，而是先筛出异常对象，再围绕节点组织附近地表积水、邻域淹没斑块、上下游管段流态和降雨强度背景，形成可追溯的诊断证据包。这样 DiagnosisAgent 的结论不是凭空解释，而是在结构化证据和关系路径约束下完成工程师式成因追溯。

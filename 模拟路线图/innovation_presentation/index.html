为什么需要 Agentic，而不是只写程序或直接喂给 LLM？

本研究不是用大语言模型替代 SWMM，也不是用大语言模型替代确定性程序；而是把传统程序的可复现计算能力，与大语言模型的任务理解、流程组织和证据解释能力结合起来。

程序负责读取模型、运行模拟、提取指标、生成证据表、核查 evidence_id。
LLM 负责理解开放式问题、组织多步骤流程、解释证据、支持连续追问。
Agentic 负责把二者串成可控工作流，避免让大模型直接面对海量原始结果。
最终产物可追溯证据链、结构化诊断 claim、unsupported rate 和解释报告。

问题一：LLM 相比传统程序的价值在哪里？

答案不是“LLM 更会算”，而是 LLM 补上了模型软件与工程决策之间缺失的认知组织层。

程序算得准，LLM 问得懂、调得对、讲得清

传统程序适合做什么

传统程序适合处理确定性强、规则清楚、需要可复现的任务，例如读取 SWMM/CA2D 输出、统计最大水深、累计溢流量、积水持续时间、按规则筛选异常对象、核查 evidence_id、计算 unsupported rate。

这些部分本研究保留为固定工具和规则模块，因为它们必须稳定、可检查、可复现。

LLM 适合补上什么

真实用户不会总用固定命令提问，而会问“这场雨哪里问题最大”“为什么这个点积水”“这个结论有什么证据”。LLM 的价值在于理解自然语言意图，并把它路由到合适的 Agent 和工具链。

它还可以把结构化证据转换成面向老师、工程师或管理部门的不同表达，支持连续追问和交互式分析。

可以直接讲给老师的一句话

本研究不是用大语言模型替代 SWMM 或传统后处理程序，而是让大语言模型工作在“模型软件与工程决策之间的认知组织层”：它负责理解任务、组织流程、调用工具、解释证据和支持追问；而数值计算、证据提取和规则核查仍由确定性程序完成。

LLM 的优势具体体现在哪里

能力具体作用
自然语言任务理解 老师、工程师或管理人员不会总是用固定命令提问，而会说“帮我看看这场雨哪里问题最大”“为什么这个点积水严重”。LLM 可以把这些自然语言意图路由到合适的 Agent 和工具链。
多步骤流程组织 它能根据当前工作流状态判断下一步该做情景准备、模拟、证据构建、诊断、核查还是报告生成，而不是要求用户记住所有命令、文件路径和执行顺序。
证据到解释的语言转化 程序可以告诉用户 Cell 115176 max_depth = 0.52 m，但 LLM 更适合把它解释为“该位置属于高风险地表积水点，应结合附近检查井溢流和管段负荷进一步判断原因”。后续如果引入立体化关系证据网和融合给排水工程师思维的诊断机制，Agentic 系统还可以沿着地表积水、检查井、管段拓扑、泵站和分区关系追根溯源。
面向不同对象生成不同表达 同一组证据，写给科研论文、应急管理部门和给排水工程师时，表达层次不同。LLM 擅长把结构化证据转化为不同受众可理解的说明。
开放式追问和交互分析 用户可以继续追问“这个点为什么严重”“有没有附近溢流节点”“如果换一场小雨还积水说明什么”。这类连续、开放、带上下文的交互式分析，是纯脚本不方便覆盖的。

问题二：为什么不直接把模拟数据或图片喂给 AI？

直接喂给 LLM 或视觉模型，看似简单，但在洪涝诊断场景中会带来 token 消耗、信息噪声、证据追溯和可靠性评价四类问题。

raw results -> structured evidence -> verified claims

直接喂原始数据的问题

一次 SWMM-CA2D 暴雨模拟可能产生几十万条节点、管段和二维元胞时序数据。直接交给 LLM 会消耗大量 tokens，而且原始表格噪声很高，关键风险对象容易被淹没。

更重要的是，LLM 即使能总结出“哪里严重”，也很难稳定说明这句话具体来自哪一行数据、哪个对象、哪个时段和哪个结果文件。

直接喂图片的问题

积水深度图或结果截图适合展示空间分布，但图片本身很难保留完整的时间过程、对象编号、指标值、阈值、排序和来源文件。

如果只让视觉模型看图，它可能能看出“哪里颜色深”，但难以严谨回答“这个 cell 的最大水深是多少、持续多久、附近节点是否溢流、证据编号是什么”。

Agentic 工作流的优点

环节它解决的问题对 AI 的好处
EvidenceBuilderAgent从海量原始结果中提取关键风险证据把几十万条时序结果压缩为对象-指标-数值-时间-来源文件结构
DiagnosisAgent把异常证据转化为结构化诊断 claim让 AI 面对的是“诊断结论对象”，而不是杂乱原始数据
VerificationAgent检查 claim 是否绑定有效 evidence_id把无证据判断显式暴露出来，并计算 unsupported rate
ReportAgent基于已核查 claim 生成解释报告让自然语言解释建立在证据链上，而不是自由发挥

这一套系统的真正价值

它不是把 AI 当成一个“万能读表器”或“看图解释器”，而是先把模拟结果整理成 AI 更容易读取、消耗更少 tokens、更加规范、更加可信、更加可追溯的数据结构，再让 AI 基于这些结构化证据完成解释和追问。

更省

减少直接输入海量时序数据造成的 token 浪费。

更准

让诊断建立在结构化证据和规则核查上。

更可信

每条 claim 都能追溯 evidence_id，无证据结论进入 unsupported rate。

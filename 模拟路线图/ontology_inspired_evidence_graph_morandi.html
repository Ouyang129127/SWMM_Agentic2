本体论启发的内涝关系证据网

将“地表积水、检查井、管段、泵站、排口、排水分区”等对象，以及它们之间的空间邻近、上下游拓扑、服务范围和证据支撑关系统一组织起来，让诊断从扁平证据筛选推进到工程成因追溯。

核心思想 不是把本体论作为额外概念堆叠，而是借用它的“对象-关系-属性/证据”组织方式，为 Agent 提供可查询、可追溯、可解释的关系化证据底座。
Layer 1

对象层 Object Layer

回答“系统里有哪些工程对象”。对象层负责给每类实体命名、编号、定位，并保留必要工程属性。

RainfallEvent 暴雨事件 SurfaceCell 地表网格 JunctionNode 检查井节点 ConduitLink 排水管段 PumpStation 泵站 Outfall 排口 DrainageDistrict 排水分区
Layer 2

关系层 Relation Layer

回答“这些对象如何相互关联”。关系层负责把坐标邻近、管网拓扑、服务范围和上下游传递路径显式表达出来。

cell_near_node node_connected_to_link link_from_node / link_to_node link_upstream_of_link pump_serves_district outfall_receives_from_link
Layer 3

证据层 Evidence Layer

回答“每个对象有什么模拟证据”。证据层把积水、溢流、充满度、流向变化等结果绑定到对象与关系上。

max_depth 最大积水深度 ponding_duration 积水时长 total_flooding_volume 节点溢流量 max_fullness 管段充满度 flow_direction_changes 流向变化次数

对象层内部内容

空间对象SurfaceCell、Subcatchment、DrainageDistrict，用于定位积水区、汇水范围和管理分区。
管网对象JunctionNode、ConduitLink、Pump、Outfall，用于表达检查井、管段、泵站和出流边界。
事件对象RainfallEvent、Scenario、Run，用于区分不同降雨、工况和模拟批次。
基础属性对象 ID、坐标、高程、管径/断面、所属分区、设计能力等。

关系层内部内容

空间邻近地表网格与附近节点、管段、汇水区之间的距离或归属关系。
管网拓扑管段起点、终点、上下游连接、节点汇入/流出管段关系。
服务关系泵站服务哪些排水分区，排口接收哪些管段或系统来水。
追溯关系从积水 Cell 追溯到附近溢流节点，再追溯到相连管段、上下游管段和末端设施。

证据层内部内容

地表证据最大积水深度、积水持续时间、发生时刻、风险等级。
节点证据总溢流量、最大溢流流量、溢流持续时间、节点水深。
管段证据最大充满度、最大流量、管内水深、流向变化次数。
核查证据claim_id、evidence_id、supported / unsupported、unsupported rate。

一个可讲给老师听的追溯链路

这条链路体现的是“工程师式诊断”：先定位风险，再沿空间和拓扑关系查找排水系统压力来源。

1. 发现积水热点 Cell 最大积水深度或积水时长超阈值，说明地表已经形成显著内涝风险。
2. 匹配附近节点 通过坐标距离或服务区归属找到承担该地块排水的检查井节点。
3. 检查节点溢流 查看节点是否发生溢流、溢流量多大、持续多久，判断管网是否向地表释放水量。
4. 追踪相连管段 查询与节点相连的上游、下游管段，重点看充满度、满流时长和流量状态。
5. 识别水力扰动 若管段频繁改变流向，可能提示顶托、回流、满管流震荡或边界排放受限。
6. 延伸到设施分区 进一步检查泵站能力、排口边界和排水分区之间的耦合关系，形成成因链。

后续可将这张概念图落成 evidence_relation_table 或 evidence_graph：每一条边都记录 source、target、relation_type、distance/topology_order、evidence_id、confidence 和 data_source，使 Agent 的诊断结论能够沿关系链逐级回溯。

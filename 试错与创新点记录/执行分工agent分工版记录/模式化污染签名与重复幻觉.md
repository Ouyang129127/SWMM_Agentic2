# 模式化污染签名与重复幻觉

## 1. 记录背景

在两次不同的 SWMM-2D-Agentic 试错过程中，后台都出现了高度相似的无关内容：

```text
两数之和
哈希表
枚举
LeetCode
nums
target
时间复杂度 O(n)
```

这些内容与当前 SWMM-2D 模型检查、CA2D 静态模型验证、项目目录查询等任务完全无关。

值得注意的是，两次失败并没有随机生成“做蛋糕”“打篮球”“微积分”等任意主题，而是都回落到中文算法题中极其典型的“两数之和”模板。这说明该问题不只是普通随机幻觉，而更像一种可重复的模式化污染。

## 2. 问题现象

前一次错误中，系统在工具调用或任务执行中断后，输出了类似：

```text
# 1. 两数之和
哈希表
rust 的 hashmap
```

本次 `run_web.bat` 后台截图中，系统再次输出：

```text
# 1. 两数之和
## 题目
## 示例
## 提示
## 进阶
## 解题思路
最简单的思路是暴力枚举...
更优的解法是用哈希表...
来源：力扣（LeetCode）
```

两次污染内容的主题、结构和关键词高度相似。

## 3. 初步判断

这类现象可以命名为：

```text
模式化污染签名
```

英文可写为：

```text
Patterned contamination signature
```

也可以作为更大问题的一种子类型：

```text
Repeated off-domain hallucination
```

中文可称：

```text
重复性离域幻觉
```

其核心特征是：

- 输出内容与当前任务域无关；
- 多次错误中出现高度相似主题；
- 内容不是随机噪声，而是固定模板；
- 常出现在工具调用失败、执行链未终止、上下文断裂或模型服务异常之后；
- 可以通过关键词签名被检测和拦截。

## 4. 可能原因

### 4.1 高频训练语料回退

“两数之和 + 哈希表 + 枚举”是中文编程语料中非常高频、结构稳定的内容。模型在失去任务约束时，可能回退到这类高概率文本模板。

这不是模型真的在解决当前问题，而是语言生成过程滑入了最熟悉、最容易展开的通用编程答案。

### 4.2 Code Agent 语境诱发

SWMM-2D-Agentic 中存在明显的编程和工具调用语境，例如：

- `CodeRunner`；
- Python 脚本执行；
- function call；
- 工具参数；
- 文件路径；
- `.inp` 文件检查；
- 自动化执行。

这些信号会让模型处于“编程任务”语域。若 SWMM 领域约束变弱，模型更容易偏向算法题模板，而不是生活、体育或数学科普主题。

### 4.3 上下文污染或历史激活

一旦某次会话中出现过“两数之和”内容，如果这些文本进入 transcript、日志、摘要或内部上下文，后续模型可能再次激活类似内容。

这意味着污染内容本身可能成为下一轮污染的触发源。

### 4.4 工具后续写阶段失控

当前现象常出现在工具调用已经完成之后。此时模型本应总结工具结果并停止，但如果内部 agent 没有强终止，模型会继续生成自由文本。

这类自由文本最容易滑入高频模板。

因此，本问题与前面记录的：

```text
post-tool hallucination
Agent 执行轨迹污染
```

高度相关。

### 4.5 模型服务端固定污染样本

由于两次污染内容高度相似，也不能排除模型服务端或中间服务在异常情况下返回了某种固定污染样本、缓存片段或评测语料。

这需要通过最小复现实验进一步判断。

## 5. 为什么不是随机主题

LLM 的失败输出通常不是均匀随机分布。它更可能回到高频、稳定、上下文相关的文本区域。

在本项目中，上下文包含大量：

```text
代码
工具
函数
路径
执行
检查
Python
Agent
```

因此模型跑偏时，最容易进入“编程题解释”轨道。而“两数之和”又是中文编程题解释中最典型的默认模板。

所以它没有随机变成：

```text
做蛋糕
打篮球
微积分
旅游攻略
```

而是稳定变成：

```text
两数之和
哈希表
枚举
LeetCode
```

这说明错误输出本身具有模式，可被识别、统计和治理。

## 6. 可发展为系统优化点

### 6.1 建立污染签名库

将重复出现的离域内容整理为污染签名：

```text
两数之和
哈希表
枚举
LeetCode
nums
target
class Solution
TreeNode
vector<int>
rust 的 hashmap
```

当内部 agent 输出包含这些高风险标记时，系统可以判定为：

```text
off_domain_contamination = true
```

并阻止其进入最终回复或会话历史。

### 6.2 区分领域词汇与污染词汇

可建立 SWMM-2D 领域词汇白名单：

```text
SWMM
CA2D
node
link
conduit
junction
flooding
rainfall
model.inp
static
events
runs
grid
flow_mask
node_to_cell_mapping
```

如果一段回复缺少领域词汇，却包含大量算法题污染词汇，则可判为离域。

### 6.3 计算离域污染分数

可以设计一个简单指标：

```text
off_domain_score =
污染词命中数 / (污染词命中数 + 领域词命中数 + 1)
```

也可以结合长度惩罚：

```text
contamination_density =
污染词命中数 / 回复总词数
```

当分数超过阈值时，系统将该回复标记为无效。

### 6.4 工具完成后强制停止

如果工具调用已经返回有效结果，则不允许模型继续自由发挥多轮文本。

策略：

```text
valid tool result -> summarize once -> terminate
```

这可以从源头减少污染内容生成。

### 6.5 污染内容不进入 transcript

即使污染内容出现在后台，也不应写入用户会话历史。否则污染会成为下一轮上下文的一部分，导致重复激活。

会话历史应只保存：

- 用户请求；
- 真实工具调用；
- 真实工具结果；
- 最终有效回答。

### 6.6 将污染检测纳入 benchmark

可以构建专门的离域污染测试任务：

- 工具调用成功后是否继续胡说；
- 工具调用失败后是否生成算法题；
- 多轮会话后是否重复激活“两数之和”；
- 前端是否能拦截污染；
- 后台日志是否能标记污染；
- 污染是否进入下一轮 transcript。

## 7. 可发展为论文亮点

这个问题可以成为论文可靠性部分的一个亮点：

> LLM-Agent 的失败并非完全随机。真实工程工作流中，模型可能表现出可重复的模式化离域污染。通过识别这些污染签名，可以构建面向工程 Agent 的输出审计与污染拦截机制。

英文表述可写为：

> We observed that off-domain hallucinations in LLM-agent execution traces were not uniformly random, but exhibited recurring patterned contamination signatures, such as algorithm-solution templates unrelated to the hydrodynamic modelling task. This motivated a signature-based contamination detection module for auditing and filtering agent execution traces.

中文表述：

> 本研究发现，LLM-Agent 在工具调用失败或执行链未及时终止时产生的离域幻觉并非完全随机，而是表现出可重复的模式化污染签名，例如反复生成与水动力模型任务无关的算法题解模板。基于这一观察，系统可进一步设计污染签名识别与执行轨迹审计机制，以提高工程 Agent 的可靠性。

## 8. 可评价指标

后续可考虑增加以下指标：

- Patterned contamination rate：模式化污染率；
- Repeated hallucination rate：重复幻觉率；
- Off-domain token ratio：离域 token 比例；
- Contamination signature hit count：污染签名命中数；
- Contamination interception accuracy：污染拦截准确率；
- Transcript contamination rate：会话历史污染率；
- Post-tool contamination rate：工具调用后污染率；
- Cross-turn contamination recurrence：跨轮次污染复现率。

## 9. 与已有创新点的关系

本记录与前面两个问题相互补充：

1. **模型结构感知工具编排与失败恢复**

   重点解决路径语义、工具选择和失败恢复问题。

2. **执行轨迹污染控制**

   重点解决工具调用成功后，内部 agent 继续生成无关内容的问题。

3. **模式化污染签名与重复幻觉**

   重点解释为什么无关内容会重复呈现为相似模板，并提出基于污染签名的检测与拦截思路。

三者共同构成 SWMM-2D-Agentic 可靠性机制的一部分：

```text
路径语义正确 -> 工具调用真实 -> 工具后强终止 -> 污染签名检测 -> 干净执行轨迹
```

## 10. 暂定结论

这次重复出现“两数之和、哈希表、枚举”的现象不是偶然小错误，而是提示我们：

> LLM-Agent 的失败输出可能具有稳定、可重复、可检测的污染模式。

这对系统设计反而是有利的。因为可重复就意味着可统计，可统计就意味着可评价，可评价就意味着可以成为论文中的可靠性贡献。

一句话总结：

> 不同于完全随机幻觉，模式化污染签名为工程 Agent 的失败检测、日志审计和输出拦截提供了可操作入口。

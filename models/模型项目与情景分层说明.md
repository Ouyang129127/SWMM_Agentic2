# 模型项目与情景分层说明

## 1. 核心原则

SWMM-2D 项目目录中需要区分两个层级：

```text
models/<model_name>/                 一个独立城市、区域或工程系统
models/<model_name>/swmm/scenarios/  该系统内部的不同 SWMM 工程情景
```

一句话：

> 不同城市、不同区域、不同管网系统，放在不同模型项目中；同一个城市或区域的不同改造方案、控制规则、工程情景，放在该模型项目的 `swmm/scenarios/` 中。

## 2. 什么是模型项目

模型项目表示一套独立的城市内涝模拟对象。通常对应：

- 一个城市；
- 一个片区；
- 一套独立管网系统；
- 一套独立二维地表模型；
- 一套节点到二维网格的映射关系；
- 一套降雨事件和模拟输出管理目录。

例如：

```text
models/harbin_swmm_2d/
models/chongqing_banan_swmm_2d/
models/songhua_swmm_2d/
```

这些项目彼此平行，地位相同。

## 3. 什么是情景

情景表示同一个模型项目内部的一种可运行 SWMM 方案。

例如在哈尔滨项目中，可以有：

```text
models/harbin_swmm_2d/swmm/scenarios/
  baseline/
  pipe_upgrade_01/
  pump_control_v1/
  storage_added/
```

它们都属于同一个哈尔滨模型项目，但代表不同工程假设：

- `baseline/`: 基线情景，通常表示现状或默认方案；
- `pipe_upgrade_01/`: 管网扩容方案；
- `pump_control_v1/`: 泵站控制规则方案；
- `storage_added/`: 新增调蓄设施方案。

每个情景目录中都应有一个可运行的 SWMM 输入文件：

```text
models/<model_name>/swmm/scenarios/<scenario_name>/model.inp
```

## 4. 哈尔滨与重庆巴南区应该怎么放

如果有两套完全不同的管网系统：

- `Model.inp`: 哈尔滨；
- `Model2.inp`: 重庆巴南区。

它们不应该放在同一个项目的 `scenarios/` 下面，而应该作为两个平行模型项目：

```text
models/
  harbin_swmm_2d/
    model.yaml
    raw/
    static/
    swmm/
      scenarios/
        baseline/
          model.inp
    mapping/
    events/
    runs/

  chongqing_banan_swmm_2d/
    model.yaml
    raw/
    static/
    swmm/
      scenarios/
        baseline/
          model.inp
    mapping/
    events/
    runs/
```

也就是：

```text
Model.inp  -> models/harbin_swmm_2d/swmm/scenarios/baseline/model.inp
Model2.inp -> models/chongqing_banan_swmm_2d/swmm/scenarios/baseline/model.inp
```

## 5. 不建议的放法

不要把不同城市或不同区域管网放成同一个项目下的情景：

```text
models/some_swmm_2d/
  swmm/
    scenarios/
      harbin/
        model.inp
      chongqing_banan/
        model.inp
```

这种放法不推荐，因为 `scenarios/` 的含义是同一个系统的不同工程方案，而不是不同城市或不同管网系统。

如果把哈尔滨和重庆巴南区放在同一个 `scenarios/` 下，会造成几个问题：

- 两套模型可能使用不同的 CA2D 静态模型；
- 两套模型可能使用不同的节点映射关系；
- 两套模型可能使用不同的地形、网格、边界和降雨事件；
- Agent 难以判断 `scenario_name` 到底是工程情景还是城市名称；
- 后续运行结果、对比分析和报告归档容易混乱。

## 6. 推荐理解方式

可以这样理解：

```text
model_name    = 研究对象 / 城市 / 区域 / 管网系统
scenario_name = 同一研究对象下的工程方案 / 控制规则 / 改造情景
event_name    = 降雨事件
run_id        = 某一次实际模拟运行
```

对应目录为：

```text
models/<model_name>/
  swmm/scenarios/<scenario_name>/model.inp
  events/<event_name>.txt
  runs/<run_id>/
```

例如：

```text
models/harbin_swmm_2d/
  swmm/scenarios/baseline/model.inp
  events/rain1.txt
  runs/test01/
```

含义是：

```text
使用 harbin_swmm_2d 这个模型项目，
采用 baseline 这个 SWMM 情景，
加载 rain1.txt 这个降雨事件，
执行一次 run_id 为 test01 的模拟。
```

## 7. 多情景示例

同一个哈尔滨模型项目下，可以放多个 SWMM 情景：

```text
models/harbin_swmm_2d/
  swmm/
    scenarios/
      baseline/
        model.inp
      pipe_upgrade_01/
        model.inp
      pump_control_v1/
        model.inp
      storage_added/
        model.inp
```

如果要比较管网改造前后效果，可以比较：

```text
models/harbin_swmm_2d/swmm/scenarios/baseline/model.inp
models/harbin_swmm_2d/swmm/scenarios/pipe_upgrade_01/model.inp
```

如果要比较泵站控制规则，可以比较：

```text
models/harbin_swmm_2d/swmm/scenarios/baseline/model.inp
models/harbin_swmm_2d/swmm/scenarios/pump_control_v1/model.inp
```

## 8. 多项目示例

不同城市或区域，应放在不同项目中：

```text
models/
  harbin_swmm_2d/
    swmm/scenarios/baseline/model.inp

  chongqing_banan_swmm_2d/
    swmm/scenarios/baseline/model.inp

  hunan_swmm_2d/
    swmm/scenarios/baseline/model.inp
```

如果用户说：

```text
检查重庆巴南区模型
```

Agent 应定位到：

```text
models/chongqing_banan_swmm_2d/
```

如果用户说：

```text
用重庆巴南区 baseline 情景跑 rain1
```

Agent 应定位到：

```text
models/chongqing_banan_swmm_2d/swmm/scenarios/baseline/model.inp
models/chongqing_banan_swmm_2d/events/rain1.txt
```

如果用户说：

```text
比较哈尔滨 baseline 和 pump_control_v1
```

Agent 应定位到：

```text
models/harbin_swmm_2d/swmm/scenarios/baseline/model.inp
models/harbin_swmm_2d/swmm/scenarios/pump_control_v1/model.inp
```

## 9. 判断规则

可以用下面的规则判断应该新建模型项目，还是新建情景。

### 应该新建模型项目的情况

- 城市或区域不同；
- 管网系统不同；
- 二维地表网格不同；
- CA2D 静态模型不同；
- 节点到网格映射不同；
- 研究对象不是同一个排水系统。

例如：

```text
哈尔滨 -> harbin_swmm_2d
重庆巴南区 -> chongqing_banan_swmm_2d
湖南某市 -> hunan_swmm_2d
```

### 应该新建情景的情况

- 同一城市或区域；
- 同一套基础管网；
- 只是工程措施不同；
- 只是管径、糙率、调蓄池、泵站控制规则不同；
- 只是为了比较现状和改造方案；
- 仍然共用同一套 CA2D 静态模型和节点映射。

例如：

```text
baseline
pipe_upgrade_01
pump_control_v1
storage_added
```

## 10. 为什么 `model.inp` 文件名可以重复

不同项目、不同情景下都可以叫 `model.inp`，因为它们所在目录不同：

```text
models/harbin_swmm_2d/swmm/scenarios/baseline/model.inp
models/chongqing_banan_swmm_2d/swmm/scenarios/baseline/model.inp
models/harbin_swmm_2d/swmm/scenarios/pump_control_v1/model.inp
```

这样做的好处是：

- 工具总能按固定路径查找；
- 不需要解析 `Model1.inp`、`Model2.inp` 这种不稳定命名；
- 项目名和情景名已经表达了文件身份；
- 每个情景目录中只有一个标准入口文件。

因此，不推荐长期使用：

```text
Model.inp
Model2.inp
harbin.inp
banan.inp
```

作为系统内部标准名称。导入时可以保留原始文件名到 `raw/`，但正式运行入口建议统一命名为：

```text
model.inp
```

## 11. 原始文件与标准入口文件

如果原始文件叫：

```text
Model.inp
Model2.inp
```

可以这样归档：

```text
models/harbin_swmm_2d/
  raw/
    Model.inp
  swmm/
    scenarios/
      baseline/
        model.inp

models/chongqing_banan_swmm_2d/
  raw/
    Model2.inp
  swmm/
    scenarios/
      baseline/
        model.inp
```

其中：

- `raw/Model.inp`: 原始文件归档，不建议直接作为自动运行入口；
- `swmm/scenarios/baseline/model.inp`: 标准化后的基线运行入口。

## 12. 总结

最终分层关系可以概括为：

```text
models/
  <model_name>/                         一个城市/区域/独立管网系统
    static/                             该系统的 CA2D 静态模型
    mapping/                            该系统的节点映射
    events/                             该系统可用降雨事件
    swmm/
      scenarios/
        <scenario_name>/
          model.inp                     该系统下某个 SWMM 工程情景
    runs/
      <run_id>/                         某一次模拟结果
```

一句话总结：

> 哈尔滨和重庆巴南区是两个模型项目；哈尔滨现状、哈尔滨管网改造、哈尔滨泵站控制规则，才是同一个模型项目下的不同情景。

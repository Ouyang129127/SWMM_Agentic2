## 1. 最终目标

每次模拟及诊断完成后，由 Report Agent 根据本次诊断 Markdown、相应结构化诊断结果、模拟数据和图像，自动生成专业、自然、便于阅读的城市内涝诊断报告。

目标不是复制某一次案例的结论，而是形成可重复应用于不同运行、降雨事件和节点集合的报告生成流程。采用“程序准备材料 → 大语言模型组织文字 → 程序渲染并检查报告”的方式。

- 程序负责事实提取、数值计算、事件和图像对应、绘图、自动标注、版式及一致性检查。
- 大语言模型负责依照章节要求表达事实与诊断，保留成因推断及共同作用关系。
- 原有诊断 MD 是内部诊断交付物；最终展示报告是另一层产物。具体职责与接口仍需讨论确定。
- 初稿编写时尚未修改正式角色；后续已接入正式ReportAgent，未改动模拟器与本案例诊断结论。

## 3. 已形成的报告共识

### 3.1 品牌与六个部分

页面主标题使用 `SWMM-Agentic`，副标题为“多智能体协同城市内涝诊断报告”。本次情景名称作为次级信息，不代替工作流品牌。

六部分结构：

1. 模拟基本场景。
2. 降雨特征。
3. 地表淹没情况与演变。
4. 管网冒溢情况与地表联系。
5. 原因分析。
6. 主要结论与关注重点。

HTML是目前采用的展示形式，能容纳GIF、静态图、节点导航和正文；打印可得到静态版。最终交付格式仍可继续讨论。

### 3.2 表达要求

- 最终报告是工作流产品，专业、自然、清楚，避免半机器语言。
- 正文不展示证据编号、字段名、机制状态清单、未提取字段、实现不足或证据缺口清单。这些保留在内部记录及论文讨论中。
- 同时保留判断强度：有支持的原因讲清楚；候选原因自然使用“可能”等措辞，不升级为已证实原因，不编造数值或因果关系。
- 成因推断与共同作用是诊断价值的核心，不能只转写发生过程或列数值。
- 全部冒溢节点应有对应分析。本样稿每节点为“发生过程＋成因判断”，配入流、出流、冒溢及水深过程图。
- 不要求每节点机械输出六项机制；根据当前诊断的实际内容组织文字。
- 暂不使用降雨等级和重现期。降雨描述采用总雨量、历时、明确时间尺度的峰值雨强、雨峰形态和雨量集中程度。
- 地表展示道路、绿地和建筑物周边的积水位置、水深、范围及演变。当前绿地按非建筑物、非道路的剩余有效地表统计；用户要求此定义放到论文说明，报告不额外解释。
- 建筑物周边积水不能改写为建筑物室内进水。地表流向与演变应以时序、空间数据或动画为依据，不凭节点顺序编造。
- 模型标识与展示名称应由程序统一转换；大语言模型不自由起区域或方案名称。

## 4. 已开发的脚本与算法

均位于：`E:\SWMM_Agentic\SWMM-Agentic2\report_previews`。

| 文件 | 已实现内容 | 通用程度 |
|---|---|---|
| `build_display_report_v1.py` | 从保存结果计算降雨、地表积水及冒溢指标，绘制初版图表，生成六章HTML并嵌入媒体 | 特定案例样稿生成器 |
| `build_display_report_v2.py` | 增加品牌、七节点独立材料和过程图、节点导航、调用自动标注算法 | 特定案例样稿生成器 |
| `build_display_report_v3.py` | 读取保存的诊断，加入七节点成因文字及内部诊断到正文的映射，保留前两版 | 特定案例样稿生成器，文字经人工组织 |
| `map_annotations.py` | `place_node_labels(ax, points)`：自动放置节点名称与引线，使用实际渲染文本框避免标签重叠、遮挡节点及越出绘图区 | 已独立的通用模块 |
| `README.md` | 样稿运行说明、自动标注调用方法、内部记录说明 | 开发说明 |
| `v1_preservation_manifest.json`、`v2_preservation_manifest.json` | 保留前两版文件的哈希清单 | 内部检查材料 |

三个生成器中的主要计算和绘图内容，可作为后续模块拆分的参考：

1. 按雨强与时间间隔积分计算总雨量；找峰值及连续30分钟的雨量集中窗口；绘制雨强和累计雨量图。
2. 按水深阈值统计同时积水面积，分道路、绿地统计；提取最大水深、面积峰值、首次积水、结束时积水、历时等。
3. 绘制各位置最大水深图、结束水深图、阶段图、地表面积与水深过程图。
4. 根据节点到网格的映射绘制冒溢节点位置并自动标注。
5. 核对事件清单与保存的节点冒溢数据；按保存时间间隔积分核对总冒溢量。
6. 提取各节点入流、出流、侧向来水、节点水深与冒溢过程，形成分析材料及过程图。
7. 生成HTML/CSS、图号、章节与节点导航、GIF重新播放按钮；将媒体嵌入独立HTML。
8. 保存指标、来源哈希、地图标注几何和诊断到文字的对应记录。

**通用化边界：**目前不能把v3生成器直接当作正式Report Agent。它固定了参考运行、节点顺序及出流管段，正文和成因段落为特定案例写定，部分时刻、比例及配色范围也按案例设置。它没有调用大语言模型自动生成任意运行的正文。后续应提取可复用计算和绘图逻辑，保留样稿作为视觉与表达参考。

自动标注模块使用确定性的候选位置搜索，不需要大语言模型猜标注位置。调用前必须完成图例、色标和子图布局；保存标注后不要再改变布局。若没有可用空间，会明确报错，后续程序可扩大画布或采用局部放大图。

样稿内部记录位于各自的 `report_preview_v*/`：`report_metrics.json`、`report_provenance.json`；v2、v3还含 `node_analysis_materials.json`、`map_label_layout.json`，以及已有的 `quality_checks.json`。

第三版已核对：数值与第二版一致、七节点诊断对应、13幅内嵌媒体可解码、前两版未变。浏览器检查过节点版面和横向溢出。这些检查针对样稿，不代表通用Report Agent已经验收。

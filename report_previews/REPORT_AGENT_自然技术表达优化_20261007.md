# 逐节点分析：回到参考报告的自然技术表达

## 参考与问题

用户指定的参考是旧运行`20261003_150049/report_preview_v3/模拟诊断报告_v3.html#causes`。本轮读取该章节的正文，参考其句子组织方式；实际试写数值仍来自当前`20261005_104641`运行的诊断r2。

上一轮逻辑改善，但“起溢”“下泄”及“起溢时，01:37……”不符合用户要的自然技术语体。提示词和教学案例本身使用了这些表达；同一峰值时刻的入流、出流与冒溢又被程序拆成不同事实句，形成重复的阶段提示和时刻。不能将这种问题单纯归于模型能力。

## 生效修改

- [新版逐节点写作指南](../workflow_agents/reporting/prompts/event_rewrite_v2.md)：采用同行技术分析语体，保留必要的入流、出流、满管、侧向来水、顶托等称谓；完整说明主体与动作，减少阶段标签和重复引导。
- [P7成对教学案例](../workflow_agents/reporting/prompts/event_example_P7_v1.json)：从参考报告学习段落组织，使用当前模拟的真实数值，示范上游与本地来水、入流增加与出流略减、冒溢增强和停止的连贯叙述。
- P6、P43、P44原教学案例同步改写，移除输出中的压缩措辞，使用同刻峰值比较。修改前案例保存在任务备份目录。
- [事实组装](../workflow_agents/reporting/narrative.py)：峰值过程有对应采样时，将入流、排出流量与冒溢峰值合成一个完整事实句，时间和节点绑定保持不变。没有对应采样时保留独立峰值句，不从其他时刻补数值。
- 同文件加入`process_comparison_anchor`：通常以开始冒溢的采样与峰值比较；峰值与开始同刻的短事件使用此前的实际采样。方向仅依据该区间的实际流量，避免把冒溢前数值与开始至峰值的变化混配。
- [生成流程](../workflow_agents/reporting/pipeline.py)版本为`report_agent_v1.5_natural_prose`。

[第二轮](./report_agent_examples/event_natural_probe_20261007_v2/逐节点分析_试写.md)加入比较区间提示后，一次调用通过程序检查，覆盖全部7个节点。P7实际引用01:37与01:40的比较，入流增加、G7出流减少；P43、P44使用冒溢前一时刻与发生时的比较，分别表现为出口出流明显下降、入流与出口出流同时回落。峰值入流、出流与冒溢量在同一句中呈现。

正文是项目当前配置模型的实际输出，未手工替换。当前轮原始输入、响应、事实标记输出、来源哈希及人工审读结论保存在各试写目录。试写只生成逐节点正文，原有HTML报告和任务状态未修改。

第二轮仍有可继续改善的表达，例如P43“全部来自本地”与100%份额重复、多个成因段落句式相近、个别标题略显生硬。其余章节尚未重新试写，不宣称整份报告已经达到参考报告的表达水平。这些开发审读事项不加入成品报告。

## 一、本例带来的核心修正

之前的问题是：“怎样的证据，才足以让我们说存在值得关注的峰值叠加？”

本例提示，应先增加一个问题：

> 这次来水过程是否具有可识别的、完整的峰值？还是持续来水逐渐进入高流量状态，且模拟在过程尚未结束时停止？

该运行采用恒定150 mm/h降雨，模拟窗口内没有独立雨峰；P42的两条来水管最大流量均出现在模拟末尾，而该节点最大Flooding出现在早期。因此，不能仅凭“两条支路的最大值时间相同”诊断为峰值叠加。

建议把第一类机制暂称为：

> 来水来源、集中过程及其与排水响应的关系。

在其中进一步区分来水规模、持续共同汇入、完整峰值叠加。该名称为讨论建议，未改写已有原话记录。

## 四、为什么先选P42

P42在Node Flooding Summary列出的累计Flood Volume约32 m³，为该表中最大值；它同时有两条来水管与直接侧向入流，适合讨论“来源识别—时间过程—替代解释”。

选它是为了展开具体机制调查，不表示它代表所有节点或整个管网的唯一根因。

### 4.1 局部连接关系

```text
P39 ─G38→ P40 ─G39→ ┐
                    │
P41 ─────────G40→ P42 ─G41→ P44
                    ↑
           B98、B92、B94、B96直接径流
```

箭头首先来自输入连接关系；本次42个报告时刻G39、G40、G41流量均为正，与这些箭头一致，不能据此保证所有未保存求解步均无短时反向。

|---|---|---:|
| G39支路 | P39、P40及直接排入它们的6个汇水区 | 0.1890 ha |
| G40支路 | P41及其4个汇水区 | 0.1563 ha |
| P42直接侧向入流 | B98、B92、B94、B96 | 0.1563 ha |

### 4.2 不能遗漏直接进入节点的水

在00:30的5分钟输出中：

- G39来水：69.7854 L/s，占节点总入流约36.16%。
- G40来水：61.0748 L/s，占约31.64%。
- P42侧向入流：62.1459 L/s，占约32.20%。
- 节点总入流：193.0061 L/s。

这三个分量在42个时刻与节点TOTAL_INFLOW相加核对，绝对差最大约0.0000115 L/s，为浮点量级。

该核对支持本例节点入流分解，但不是完整水量闭合验证，也不保证所有网络、所有管段的输出都能直接这样相加。

本例没有INFLOWS、DWF、RDII输入；四个直接汇水区确实需要纳入来水调查。只追“上游管段的上游”会遗漏约三分之一的节点入流。

### 6.1 可以确认的事实

- G39、G40全程最大流量均在03:30；RPT Link Flow Summary也给出相同极值时间。
- P42直接进入的四个汇水区，其5分钟输出最大径流均在03:30。
- P42总入流最大值在03:30，而Flooding最大值在早期。
- 在所列时刻，后期总入流总体较大，Flooding却总体减小，水头继续上升。
- 03:30时P42仍有正Flooding，模拟尚未提供停雨后的恢复阶段。
- 输入井底1046.923 m，最大水深1.075 m，模型井口参考高程为1047.998 m；不能直接当成独立测量地面。
- G41下游P44在00:10水头约1047.886 m，而其模型井口参考高程1047.744 m，说明相邻节点同样处于高水位状态。

### 6.2 不能据此声称的结论

- 不能说“雨峰后6分钟溢流”：输入没有唯一雨峰，00:06也不是起始时刻。
- 不能说“两条管峰值同时发生，证明它们造成初次溢流”：最大值在窗口末端，不能解释约00:06的峰值发生。
- 不能把03:30的全窗最大值直接识别为完整水文峰。没有观察到其后的下降段。
- 不能说后期Flooding减小就说明系统已经恢复：水头仍高，仍有正溢流，未观察退水。
- 不能因G41与上游两管均为DN400，就认定该管无问题或必然是瓶颈。

### 6.3 更合理的当前解释

> P42接收两条支路来水和较大的直接侧向入流。在恒定强降雨下，这些来源持续共同汇入。节点早期出现Flooding，之后在较高水头下出流逐渐接近入流，新增溢流速率总体减小。现有资料支持继续调查持续来水与网络输水、蓄泄响应之间的关系；不足以将该过程确认为独立洪峰的时间叠加，也不足以将上游来水或G41单独定为主因。

此解释仍保留早期数值变化、局部输水约束和下游内部回水等竞争解释。水头差与流量存在物理联系，但本次没有通过对照运行确认主导因素。

## 七、必须保留的模型口径问题：Flooding与ponding

本例ALLOW_PONDING=YES，节点存在非零Ponded Area。RPT一方面报告P42 Flooding累计约32 m³，另一方面Flow Routing Continuity的Flooding Loss显示0.000（以报告精度为准）。

这两项并不直接矛盾：节点越井/蓄水统计与从整个一维系统永久损失的水量不是同一口径。EPA手册说明ponding水可暂存在节点并在条件允许时返回管网。[S1]

源代码中Hours Flooded在“节点容积超过满容积，或overflow为正”时累计。因此RPT的3.39 h不能直接当作严格正溢流流量的连续时长。[S2]

本次框架需同时区分：

1. 正向Flooding流量事件。
2. 节点高水位或ponding持续状态。
3. 整体水力过程是否恢复。

即使正向流量间断，高水位状态仍可能持续；这正是先识别事件片段、再判断过程关联的必要性。

当前CA2D读取node_flooding.tsv作为输入，而SWMM自身仍保留ponding状态。若进一步评价整个SWMM–CA2D组合的水量闭合与来源贡献，必须另行核查水量是否重复保留、回流如何处理及采样输入一致性。本次没有把该风险宣判为已完成证明的耦合错误，也没有修改配置。

特别注意：工具枚举名PONDED_VOLUME不能不经核查就解释成纯地表积水体积。SWMM node_getResults的NODE_VOLUME输出是节点模型容积；须按源代码和对象状态确认口径。[S3]

## 八、第一诊断框架建议修订为七个步骤

### 第0步：判断本例能检验什么

识别雨型、模拟窗是否完整、是否有可用峰值、采样分辨率、模型机制及设置。

本例可检查来水组成、持续共同汇入、初期水位与出流响应；不能完整检查退水，也不能用终点最大值验证典型双峰叠加。

### 第1步：列出进入节点的全部来水路径

相连管段按实际流量方向判断，加上直接侧向入流。明确哪些来源已经包含在节点TOTAL_INFLOW中，避免重复加总。

P42应列G39、G40与四个直接汇水区，而不只列两条上游管。

### 第2步：先描述形态，再讨论叠加

区分：

- 有明确上升与下降的峰值过程；
- 有一定宽度的高流量平台；
- 持续共同来水；
- 多轮脉冲或局部波动；
- 在模拟末端仍上升、尚未完整记录的过程。

平台起止、局部峰显著性及容差待讨论，不能针对本例临时挑一个阈值以得到预设结论。

### 第3步：锚定“四问”的目标时段

解释起始必须重点查看起始前后。解释累计体积则查看完整可用时段及删失情况。不能使用远在溢流之后的全场峰值解释起始。

本例早期数分钟的细过程无法从5分钟数据完整恢复，RPT峰值恰好暴露了这个缺口。

### 第4步：比较来水变化与出流、水位、蓄泄响应

在同一窗口比较，而非分别挑最大值。初步入流分解核对与严格控制体水量闭合必须分开。Ponding条件下，不能将overflow既作为控制体永久外排，又重复计入控制体内部储水增长。

本例应继续查看00:00—00:20的变化，尤其是G41出流及P44水头，而不是仅追上游支路峰值。

### 第5步：区分三个不同的“贡献”

- 某时刻来源流量占总入流比例：本例可计算，例如P42直接侧向入流在00:30占32.20%。
- 来源在一个时段的来水体积占比：需要正确积分和路径口径。
- 某来源对溢流或热点的因果贡献：不能用前两者替代，需要额外设计验证及处理机制交互。

### 第6步：输出分层结论与下一步建议

本例可以写：
- 事实：多来源持续共同汇入，直接来水不可忽略。
- 候选解释：持续来水与输水、蓄泄响应共同作用。
- 未确认：短时峰值叠加主导、G41唯一瓶颈、下游内部回水贡献大小。
- 不适用的已建模机制：本运行未建泵闸和时变外河水位边界。
- 数据限制：起始分钟级细过程缺失，退水段缺失。

## 九、LLM在这个真实例子中应该做什么

理想调查表达应类似：

> 我发现输入是恒定雨强，且来水最大值都在模拟末尾，因此暂不采用全窗峰值时间差判断叠加。P42还有占比约三分之一的直接侧向入流，应补入来源分解。起始阶段的RPT峰值被5分钟输出遗漏，需要先说明证据缺口，再决定是否请求细时步数据。现有数据还提示下游相邻节点高水位，应将出流响应与局部水头共同纳入调查。

这里LLM选择适用假说、修正调查路径、识别缺口；程序提取和核对数值。不能让LLM自行补出00:06各支路的瞬时流量。

## 十、建议下一步及授权边界

先用P42讨论“持续共同来水”如何区别于“峰值叠加”，以及高水位持续但Flooding衰减如何解释。暂不制定固定峰值时间差阈值。

若后续需要补证据，可提出一个独立的新运行方案：

- 保持原模型与雨型不变，增加起始阶段高频输出，以检验早期瞬态及报告步遗漏。
- 另设延长模拟窗口的方案，观察既定降雨结束后的恢复。必须明确00:03:30处最后一个雨量记录的有效区间，不能简单延长结束时间后宣称雨已停止。
- 数值时间步敏感性验证与改变水力条件的因果对照分开。
- 如最终研究峰值叠加，应选择或设计确有可辨识峰形的来水过程，而非强迫本恒定雨型承担所有验证任务。

上述仅为建议。本次没有运行新模拟，没有改变降雨、边界、ponding或控制规则。

## 十一、质量与解释审查

RPT报告径流连续性误差0.913%、路由连续性误差-0.011%；1.35%的路由步未收敛，最大不稳定指数列出G79、G80等。这些是需要保留的质量线索。全网水量误差小不保证每个早期峰值可靠，也不能因存在这些指标就宣布P42结果全部无效。

本次不涉及p值、置信区间或统计显著性检验。按研究核查技能检查11项解释风险：

| 项目 | 本次处理 |
|---|---|
| Simpson悖论 | 未开展分组相关或回归，不适用 |
| 生态谬误 | 不从全网连续性误差推出P42局部可靠性 |
| Berkson选择偏差 | P42按大体积和汇合结构选取，只作案例，不外推发生率 |
| 碰撞变量偏差 | 未开展控制变量因果回归；不由已溢流样本估计普遍因果关系 |
| 基率忽视 | 未评估诊断准确率或概率，不适用 |
| 均值回归 | 无前后干预实验，不把后期溢流下降称为改造效果 |
| 生存偏差 | 不把未结束事件当成已完整恢复 |
| 多重搜索 | 未做显著性筛选；披露节点选择理由 |
| 分析路径自由度 | 明示为探索性框架修订，未设事后最优阈值 |
| 相关当因果 | 来水同时较大不直接证明溢流主因 |
| 反向因果 | 管网水头可影响支路流量，支路波动不一定是独立上游驱动 |

覆盖11/11；不适用项已说明。无SWMM重跑，复现状态为“已核对既有结果，未验证重新求解的一致性”。

### 二进制读取方法

使用项目.venv中的Python和swmm.toolkit.output：

1. output.init / output.open只读打开model.out。
2. get_proj_size返回[218, 100, 97, 1, 0]；get_times(NUM_PERIODS)=42；REPORT_STEP=300 s。
3. 使用get_elem_name匹配节点、管段及汇水区ID，不假定ID等于数组下标。
4. get_node_series读取HYDRAULIC_HEAD、LATERAL_INFLOW、TOTAL_INFLOW、FLOODING_LOSSES；get_link_series读取FLOW_RATE；get_subcatch_series读取RUNOFF_RATE。
5. startPeriod=0，endPeriod=41；报告时刻为起始后的5、10、…、210 min。
6. 流量按文件LPS单位解释；最后关闭句柄。未调用Simulation求解接口。
